# Homecraft 多人在线模块（multiplayer）设计与实施计划

## Context

小岛站（石兴龙的小岛）目前是纯单机静态站。目标：加一套**可独立分享的多人在线模块**——任何访客打开网页即进入"游戏"，以 `Token-xxxx` 名字和随机皮肤出现在岛上，彼此看到走动/飞行等动作，可用"当前频道"式群聊（无历史、无存储）。服务器挂掉时网站完整可玩，只是没有同步。

已确认的决策：
- **服务端**：Node.js 独立服务（`ws` 库），可部署到任意 VPS / Docker
- **规模**：10–50 人同时在线 → 远端角色用**实例化角色池**渲染（第二阶段）
- **身份**：首次访问生成 uid + 随机皮肤种子，**存 localStorage 固定**
- **聊天**：聊天记录（左下角淡出）+ 头顶气泡

### 需求映射

| # | 需求 | 实现点 |
|---|---|---|
| 1 | 进站即游戏 | 客户端随 `world/build.js setup()` 自动启动，endpoint 为空则整体关闭 |
| 2 | 默认名 Token-xxxx | `identity.js`：`Token-` + uid 后 4 位 hex |
| 3 | 随机角色皮肤 | `skins.js`：种子驱动程序化生成 64×64 皮肤（零图片资源），随机一次后固定 |
| 4 | 动作同步 | 10Hz 状态增量（位移/朝向/模式/速度/手机），客户端插值 + 本地合成动画 |
| 5 | 服务器宕机可玩 | 连不上 = 完全静默单机；自动指数退避重连（1s→8s+抖动），重连后重新 join |
| 6 | userId 存 localStorage | `homecraft.mp.uid`（crypto.randomUUID） |
| 7 | 群聊无历史 | 服务端纯转发、内存态、零持久化；聊天消息不落盘 |
| 8 | 模块独立可分享 | 单一 `multiplayer/` 文件夹（client+server+README+协议文档），复制即可用，**引擎零改动** |

## 架构总览

- **零引擎改动**：挂载点用 `world/build.js` 的 `setup()`（引擎每帧调用其返回的 `update`，启动时调用 `warmup`）；配置走 `home.config.js` 顶层新字段 `multiplayer`（`engine/config.js:34` 浅合并会透传未知键，模块自持默认值）。
- **降级姿态**：与 `backend/mailbox` 一致——endpoint 空 / 连接失败 / 被拒 = 无任何 UI 残留，行为与今天完全相同。
- **房间**：按请求 Origin 分房间（WS 握手自带 Origin），服务端 `SITE` 白名单控制谁能连；`*` 可开放为公共服务器。一个服务器可同时服务多个站点，互不可见。

粘合改动（仅 3 个现有文件，小改）：
- `world/build.js`：新增 `setup()`，约 8 行——import `createMultiplayer`，异常静默捕获（setup 抛错会让整站进纯文本模式，必须 catch），把返回的 `update/warmup` 并进 extras
- `home.config.js`：`multiplayer: { endpoint: 'ws://127.0.0.1:8787', maxRemote: 24 }`
- `tools/build.sh`：复制清单加 `multiplayer`

## 协议 v1（JSON over WebSocket，文本帧）

Client → Server：
- `join { v:1, type:'join', id, name, skin }`，skin = `{k:'seed', s}` | `{k:'png', d≤24000}` | `{k:'default'}`
- `state { v:1, type:'s', x, y, z, ry, m, sp, run, ph }`（m: 0 地面/1 腾空/2 飞行/3 游泳；ph: 手机是否拿出）
- `chat { v:1, type:'c', t≤120 }`；`ping { type:'p' }`

Server → Client：
- `welcome { type:'welcome', id, players:[{id,name,skin,位置态}…] }`（迟到者直接拿到在场名单）
- `join / leave / state(id 不回显发送者) / chat / pong / kick{code:'replaced'|'full'|'slow'}`

服务端规则：Origin ∈ SITE；同 id 新连接挤掉旧连接（`replaced`）；限流 state≤20/s、chat≤4/10s、join≤3/min、单帧≤2KB；房间人数 ≤ MAX_PLAYERS(50)，满员拒绝（客户端静默单机）。**服务端只转发，不存任何东西**。

## 客户端要点

**identity.js**：uid（`crypto.randomUUID()`）、`Token-xxxx` 名、skinSeed 都存 localStorage，首次生成后固定；若有 portal 旅行会话携带的皮肤（`sessionStorage`，`engine/traveller.js` 的 `wornSkin()`）则优先用真实 PNG。

**状态同步**：本地每帧对比采样——位移 >5cm / 朝向 >3° / 模式切换 / 手机开关才发送，静止时 3s 心跳；发送用 `setInterval`（帧循环在后台标签页会停，心跳不能依赖它）。远端每个玩家保存最近 2 个状态，按 `now−150ms` 插值（位置 lerp + 朝向最短弧），>3m 跳变视为传送直接吸附；动画（摆臂/飞行/游泳）由插值速度本地合成，不传输动作帧。游泳姿态为简化版（不传 pitch/roll，引擎 player 内部状态未暴露，可接受近似）。

**聊天 chat.js**：
- `T` / `/` 呼出输入框（引擎 `input.js` 对 input/textarea 目标自动放行，这两个键空闲），Enter 发送、Esc 关闭，呼出时 `preventDefault`
- 左下角日志：最多 5 条、12s 淡出、`textContent` 渲染（XSS 安全，符合 portal 协议"文本不当身份"的立场）；进/出岛系统提示；在线人数小字
- 头顶气泡：每人一个 DOM 元素，`camera.project` 每帧定位（复用 scratch Vector3，零分配），6s TTL，出视野/背后自动隐藏
- 空日志时显示一行像素风格提示「按 T 聊天」，风格复用引擎 `#prompt` / `--gui` / `--ink` 变量（自动适配 `body.night`）

**远端渲染（核心）**：

- **阶段 1（remote.js，先打通链路）**：每玩家一次 `createAvatar(skinUrl)`（`engine/world/avatar.js` 闭包工厂、无全局状态，支持各穿各皮肤；皮肤经 `engine/door-protocol.js` 的 `decodeSkin()` 校验）。上限 4–6 人（超出按距离隐藏）。注意三件事：① spawn 时手动 `world.lighting.apply(root)`（在引擎 812 行预热之后才生成，需自己补光）；② blob 阴影是独立 mesh 需自己放置（`nav.heightAt`）；③ 离场时手动 dispose（createAvatar 无 dispose 方法，9 几何体 + 4 材质 + 1 纹理）。
- **阶段 2（remotePool.js，解锁 10–50 人）**：仿照 `engine/world/blocks.js` 的 BoxBatch + `avatar.js:242` petRig（12Hz 矩阵上传先例）：**7 个 InstancedMesh**（头/帽/躯干/双臂/双腿，单位盒 + 实例矩阵缩放）+ **1 个 blob 实例池** = 全部远端玩家共 8 个 draw call。皮肤走 64×64 **纹理数组**（`engine/world/textures.js` 的 `createTileArray` 模式），每实例 slot 映射一层，自定义实例属性传 UV 偏移 + 层号，`onBeforeCompile` 补丁采样——照抄 blocks.js 的既有做法。矩阵上传 15Hz、容量预分配（默认 32，`maxRemote` 可调）、count 随人数增减，每帧零分配。
- 预算核验：阶段 1 桌面 23+4×8=55 ≤60，移动 16+4×8=48 ✓；阶段 2 全量 23+8=31 ✓（32 人 ≈3.5k 三角形，可忽略）。

## 里程碑（增量交付，每步可独立验收）

- **M1 全链路打通**：server + net + identity + skins + chat + remote.js 直渲染。验收：本地起 `node multiplayer/server/server.js` + `python3 tools/serve.py`，双浏览器窗口互相看到走动/飞行/皮肤/名字/聊天/气泡；刷新身份不变；杀掉 server 页面照常玩、重启自动重连。
- **M2 实例化角色池**：remotePool.js 替换直渲染，server 加 `--bots 20` 假人模拟器（随机走动的假状态），单页面即可压测 20+ 人同屏与预算。
- **M3 分享包打磨**：README + PROTOCOL.md + Dockerfile；`tools/check-multiplayer.mjs`（Playwright 双页面对拍，复用 check.mjs 模式）+ `npm run check:mp`；跑 `npm run check` 确认引擎零 diff、`?debug` 预算达标。

## 验证方式

1. `node multiplayer/server/server.js`（默认 :8787，`SITE` 默认 `*` 便于本地试）
2. `python3 tools/serve.py`，`home.config.js` 填 endpoint
3. 双窗口对拍：位置/朝向/飞行/游泳/手机/聊天/气泡/进出场提示
4. 降级：endpoint 置空、server 停机、错 Origin、满员 → 页面均完整可玩、无报错残留
5. `npm run check`（check:site 引擎 diff 应为零）+ `?debug` 截图对比 draw calls / 三角形
6. `npm run check:mp`：自动化双页面对拍

## 非目标（v1 明确不做）

- 改名 UI（协议里 name 就是普通字符串，未来可加）
- 历史消息 / 离线消息 / 任何持久化
- 小地图他人蓝点（minimap 不在 setup 暴露面里，需动引擎——按约定先征询，列为后续可选项）
- 鉴权/防伪（身份非认证，与 docs/protocol.md 立场一致；README 说明公共部署的限流边界）
- 兴趣管理/AOI（岛仅 74×57 格，全房间广播：50 人 ×10Hz ≈ 50KB/s，Node 单进程毫无压力）
